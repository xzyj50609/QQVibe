句豆 · ChatBean 使用手册

1.0.0 界面与操作

QQVibe 的新显示名称为 句豆 · ChatBean。新界面采用浅蓝渐变、紧凑会话列表、圆头像和 QQ 风格引用气泡。聊天与画像可从顶部或左侧切换，返回聊天保留阅读位置。没有常驻成员右栏；群成员筛选仍在「聊天记录」，群画像仍可「选择成员」。

点击搜索框旁的 ＋，选择联系人或群聊，填写 QQ 号/群号后添加到分析列表。未连接时按提示进入「连接与导入」；原来的好友读取、按号码添加、JSON 导入入口仍在设置中。

联系人列表与聊天区之间的分界线可以左右拖动，松手后记住宽度。双击恢复默认；键盘聚焦分界线后，左右方向键微调，Delete 恢复默认。原主题、模型和标签设置不受影响。

新用户默认显示标签百分比，已有用户主动保存的简洁选择保留。百分比是候选值，不是判断准确率。下方草稿仍然只复制、不自动发送。软件更新入口仍是「设置 → 关于 → 当前版本」。已有数据、模型和更新源保持兼容，文件夹仍名为 QQVibeData，程序仍为 QQVibe.exe。

本节是下一版说明，不能据此认为线上 0.1.2 已包含这些变化。下面保留旧版通用使用步骤和截图；功能入口变化以本节为准。

QQVibe 用来回顾自己选择的 QQ 单聊和群聊。它把原始消息、模型标签与人物画像放在同一应用里，方便你回看交流、查找上下文。第一次安装和连接请先看首次使用说明。解压目录的 「使用说明.html」可在浏览器中离线打开。

本文和截图中的账号、昵称与聊天都是演示资料，分析内容仅作界面展示。

认识主界面

演示数据，分析内容仅作界面展示。

  • 会话列表：切换已经添加的单聊或群聊。
  • 消息区域：阅读消息原文、时间与发言人，查看已经生成的分析标签。
  • 「聊天记录」：搜索关键词、日期，群聊还可以筛选成员。
  • 「情绪 / 意图」与「人物画像」：查看消息标签，或切换到当前会话的画像页面。
  • 设置：连接 QQ、选择模型、管理会话和账号、备份与恢复。

QQVibe 新用户默认使用浅色界面。恢复旧版设置后仍为深色时，在 「主题外观」中选择 「浅色模式」即可。字太小可在设置中调整 「界面缩放比例」。

看单聊

演示数据，分析内容仅作界面展示。

  1. 在左侧会话列表打开一个单聊。
  2. 先核对对方昵称和消息中的身份归属，确认「我」没有被当成对方。
  3. 保持 「情绪 / 意图」开启，查看消息旁的分析标签。第一次分析需要等待，已有消息可以继续阅读。
  4. 想看模型分数时点 「百分比详情」；想恢复简洁显示时点 「切回简洁」。
  5. 点 「人物画像」，在页面上切换 「我」和 「对方」，查看双方分别在这个单聊里的画像。
  6. 点 「返回聊天」回到消息。

标签和画像是模型对这段聊天的推测。分数高不等于判断一定正确；人物画像也不是心理测评。样本不足时会显示「待判断」或尚未解锁，继续积累足够文本后再看。

看群聊

演示数据，分析内容仅作界面展示。

  1. 打开已经添加的群，核对群名、发言人和群名片。
  2. 阅读消息时结合上下文看标签。本地群聊标签目前是实验候选，引用、转发、讽刺和多人对话可能被误读。
  3. 点 「人物画像」，先看 「群概览」。这里的消息数、文本数和参与人数对应已读取范围，不是全群全部历史。
  4. 点 「选择成员」，搜索并选择一位具体成员，查看他在这个群里的画像。
  5. 换成员时核对当前成员名称。群画像只来自此人在这个群里的发言，不会把其他所有人拼成一个「对方」。

成员列表中没有某个人时，可能是当前已读范围里没有他的发言，不代表他不在 QQ 群内。

演示数据，分析内容仅作界面展示；图中的标签不代表已完成语义质量验证。

搜索旧消息

  1. 在会话右上方点 「聊天记录」。
  2. 输入关键词，按需要选择日期；群聊可以选择成员。
  3. 点 「搜索」，打开某条结果查看它前后的消息。
  4. 需要继续往前看时点 「加载更早」。
  5. 看完后点 「返回最新」回到当前消息。

搜索的是 QQVibe 已读取或导入的记录。没有搜索到，可能是当前范围还没有这段消息；请查看设置中的 「当前会话的数据范围与管理」，不要把搜索不到当作 QQ 原记录已被删除。

添加和管理会话

在线会话通过设置的 「QQ 连接与自动同步」添加：

  • 点 「读取 QQ 好友」选择好友，或填写对方 QQ 号点 「添加单聊」。
  • 填写自己选择的群号，点 「添加群聊」。

在设置的 「信息列表 → 管理会话」中，可以把已保存会话加入左侧列表，或从列表移除。「从列表移除」只是调整显示；清理已读消息需要使用专门的本地副本管理入口。

首次添加默认有最近 90 天、最多 200 条的读取边界。页面若提示未读完、缺口或部分范围，就按当前范围理解统计。QQVibe 不承诺取得 QQ 所有漫游历史。

新消息、暂停和取消

保持 QCE 登录、QQVibe 正常运行，并启用对应会话的读取后，程序会同步已选会话的新消息。分析与读取分别进行，模型慢时仍然可以先阅读。

操作会发生什么
「暂停分析」保留尚未完成的分析范围，已完成结果保留，消息读取与浏览继续
「继续分析」继续处理暂停后尚未完成的范围
「取消分析」取消尚未完成的范围，已完成标签保留
设置中的「停止读取此会话」停止这个会话后续读取，已有本地记录仍可查看

API 模式下，暂停或取消前已经发给服务商的请求可能继续结束，也可能计费。界面中的请求上限控制接下来允许发出的次数，不替代服务商自己的费用预算；没有费率时只显示次数。

如果连接中断，先确认 QCE 仍然运行、账号仍已登录，再回到设置重连。不要在身份不确定时反复添加会话。

关闭和重新打开

  1. 正常退出 QQVibe。
  2. 下次从同一个解压目录打开 QQVibe.exe。
  3. 如出现已保存账号入口，选择自己的账号查看记录。
  4. 已保存消息和分析结果可以离线浏览；需要继续同步时重新确认 QQ/QCE 连接。

请保留原解压目录。解压到新文件夹相当于使用另一份便携程序，不会自动从旧目录读取数据。

备份、升级和恢复

第一次使用成功后，以及更新前，在设置的 「完整数据备份与恢复」中点 「备份全部数据」，把备份保存到自己的目录。

备份包含聊天和账号配置，属于私人资料，不要随反馈上传。模型文件不包含在备份内；自行选择的外部模型文件夹也需要另行保留。

升级时先保留旧程序，把新版解压到另一个目录，再通过 「恢复备份」导入旧备份。不要直接覆盖运行中的程序。恢复后核对账号、会话、消息与结果，再重新连接；换电脑或 Windows 账号后需要重新配置凭证。

详细步骤见备份、升级与回退。跨机恢复仍在验证，旧目录和原备份应保留到新版确认可用。

导入已有 QCE 文件

1.0.0 支持更多列表结构、字段映射和大文件分批读取，并自动识别 QCE 6.3.0/6.3.1 的时间、编号与文本类型。具体用法见 JSON 导入说明。

已有 QCE 导出记录时，可在设置中选择导出文件，确认「哪一个 QQ 号是本人」，查看预览后再确认导入。支持的入口包括 QCE 单 JSON 与分块 manifest 文件，具体会话类型以导入预览为准。

导入是在本机补充历史，不代表已经连接在线 QQ；要同步自然新增的消息，仍需正常登录 QCE 并连接。

删除自己的本地副本

在设置的 「当前会话的数据范围与管理」中使用 「清除此会话副本」。清除前按提示保留备份，核对会话后再确认。它清除的是 QQVibe 本地消息和分析副本，不删除 QQ 原始记录。

账号级清理通过 「查看账号」内的管理入口进行。不要靠手工删除数据库文件解决连接或分析问题。

遇到问题时

先查看已知问题和兼容表。仍无法解决时：

  1. 记录版本和最后失败的步骤。
  2. 到设置的 「关于句豆 · ChatBean」中点 「导出诊断信息」。
  3. 打开诊断文件自行检查后，将匿名诊断与错误提示发给提供软件的同学，或按反馈模板提交。

诊断用于记录版本、状态与计数，不需要聊天正文、账号标识或密钥。截图必须遮住账号、昵称、头像、群名和消息原文。不要上传数据库或完整备份。

第一次在另一台电脑使用时，可直接填写一页试用清单，未尝试的项目留为「没试」即可。

句豆 · ChatBean 首次使用说明

这份说明面向第一次使用句豆的人。完成后，你可以在句豆中打开自己的一个单聊或群聊，并查看本地分析结果。不需要会编程。程序旁的 「使用说明.html」也可直接打开，离线查看图文步骤。

1. 下载正确的程序包

点击 下载 QQVibe 1.0.0 Windows 完整包。如果不能直接下载，打开下载页面，在下方的 Assets（文件列表）里点击：

QQVibe-1.0.0-windows-x64-full.zip

这个文件包含程序和 Laya 模型，第一次使用优先选它。不要下载「Source code」或点击绿色「Code」按钮，那些是给开发者的源码。公开下载不需要注册 GitHub 账号。

目前提供 Windows x64 程序，推荐先在 Windows 11 上使用。Windows 10、其他电脑与更多硬件的实际情况见兼容表。

2. 解压并打开

  1. 下载完成后，在 ZIP 文件上点右键，选择「全部解压缩」，或使用你平时的解压软件。
  2. 解压到自己可以保存文件的普通目录，例如 D:\Apps\QQVibe；没有 D 盘也可以放在自己的「文档」文件夹。不要放在压缩包内或系统的「Program Files」目录。
  3. 打开解压后的文件夹，再打开 win-unpacked。
  4. 双击 QQVibe.exe。

QQVibe 是便携程序，数据保存在解压目录内。以后移动程序时请一起保留整个文件夹，升级前先做备份。新用户默认浅色；如果从旧版恢复了深色设置，可在设置的 「主题外观」中选择 「浅色模式」。

应用目前未签名，Windows 可能显示安全提示。先确认下载来自上述仓库；不确定时把提示文字发给提供软件的同学，不要为此关闭安全软件。下载页提供 SHA256 校验文件，熟悉校验的人可以用它核对 ZIP。

3. 安装并登录 QCE

QCE 的全名是 QQ Chat Exporter。它负责在你的电脑上连接 QQ，QQVibe 再从它读取你选择的聊天。它是单独安装的软件，不在 QQVibe ZIP 里。

  1. 打开 QCE 6.3.0 官方下载页面。
  2. 在 Assets 文件列表中下载 QQChatExporter-Installer-v6.3.0.exe，这是 Windows x64 的一键安装包。
  3. 双击安装文件，跟着它的向导安装并启动。
  4. 在 QCE 中用自己的 QQ扫码或快捷登录。
  5. 确认 QCE 显示的是自己的账号，能看到会话列表，然后保持 QCE 运行。

如果 QCE 提示在浏览器打开界面，使用它给出的本机入口；默认通常是 http://localhost:40653/qce。这个地址只有准备好 QCE 的那台电脑可以使用。

本说明固定使用 6.3.0，方便定位问题。QQ 与 QCE 的变化可能影响连接；若安装或登录失败，记录版本和提示，不要盲目反复更换 QQ 版本。

如果一直显示「正在生成二维码」或「NapCat WebUI 未响应」，使用单独的检测工具包；集成此功能的新构建版也提供程序旁的 「检查并修复QCE.cmd」。它自动检查启动各关口，提供适用的最小修复和复检，不需要自己翻日志。操作见检测与修复说明。

我已经用过 QCE 或 NapCat，想沿用自己的安装

已有桌面 QQ 并使用 Framework 模式的人，可以从同一官方发布页下载 NapCat-Framework-QCE-v6.3.0.zip，完整解压，完全退出 QQ 后运行 napiLoader.bat，再登录自己的 QQ。这与上方的一键安装二选一，不要求先安装 LiteLoader。

自定义安装目录、端口或访问 token 的连接方式见本文末尾「高级连接」。standalone 的离线浏览模式不能提供在线新消息。如果不熟悉这些名称，使用上方的一键安装路线即可。

4. 在句豆中连接自己的 QQ

  1. 回到 QQVibe，点击 「首次设置：连接 QQ、选择模型与会话」。
  2. 在 「QQ 连接与自动同步」中点击 「连接本机 QQ / QCE」。
  3. 等待连接状态更新，核对显示的是自己的账号。
  4. 如果提示 QCE 没有运行或没有登录，回到 QCE 完成上一步，再重试。

标准安装由程序寻找受控配置，不需要你翻日志找 token。没有连接成功前，不必填写好友或群号。

演示数据，分析内容仅作界面展示；截图未连接真实 QCE，不表示连接已通过。

5. 选择本地 Laya / CPU

在设置中找到模型区域：

  1. 「模型来源」选择 「本地部署」。
  2. 「模型设备」选择 「CPU」。
  3. 查看 「模型文件」与设备状态，等待模型就绪。
  4. 如果出现 「启用本地模型」按钮，点击它。

Laya 是用于分析文字的本地模型。完整包已经带有它，一般不需要再下载。先选 CPU，走通第一次使用后再考虑 GPU；目前只有开发机的 Intel UHD WebGPU 有实测，其他显卡仍在验证。

演示数据，分析内容仅作界面展示；模型文件提示与运行时是否就绪应分别看，截图不代表完成真实推理。

如果提示缺少模型，先检查自己是否下载了文件名带 -full.zip 的完整包，以及是否完整解压。你也可以按下方「无模型标准包」的步骤准备模型，界面和 API 设置仍然可以打开。

6. 添加一个单聊或群聊

第一次先添加一个你有权读取的聊天，不要一开始就添加很多会话。

添加单聊：

  1. 在 「QQ 连接与自动同步」中点 「读取 QQ 好友」，找到要查看的好友并添加。
  2. 也可以在 「或填写对方 QQ 号，仅添加此单聊」下面填写对方 QQ 号，点 「添加单聊」。
  3. 关闭设置，在左侧会话列表打开这个聊天。

添加群聊：

  1. 在 QQ 中查看这个群的群号。
  2. 在 「添加你明确选择的群聊」下填写群号，点 「添加群聊」。
  3. 关闭设置，在左侧会话列表打开这个群。

首次添加会话会有范围限制，默认读取最近 90 天、最多 200 条记录；实际已读范围和历史缺口以页面提示为准。这不等于 QQ 的全部历史记录。

7. 查看分析，完成第一次使用

打开会话后，消息可以先浏览，分析结果会逐步出现。确认下方的 「情绪 / 意图」已开启；需要查看画像时点 「人物画像」。

  • 单聊：在画像页面切换 「我」和 「对方」，分别查看双方在这个单聊中的交流情况。
  • 群聊：先看 「群概览」，再点 「选择成员」查看具体成员在这个群里的画像。

群聊标签是实验候选，可能误读引用、讽刺或多人对话。百分比不是准确率；画像也不是对人的定论。显示「样本不足」「待判断」时，不代表程序损坏。

接下来可以按使用手册了解搜索和分析控制，按第一次试用清单记录这台电脑的结果。第一次走通后，在设置的 「完整数据备份与恢复」中做一份备份。

无模型标准包：下载或选择模型

如果你已经有模型，或希望自己配置服务，可以下载标准程序包。它不含 Laya 模型，程序本身仍可启动。

  • 在「本地部署」下点 「下载模型」，等待下载与检查完成。下载失败可以重试，不会妨碍进入 API 设置。
  • 已有完整 Laya 文件夹时点 「选择目录」，选择包含 model.onnx 的目录；不要只选其中一个文件。选定的外部模型目录以后也要保留。

演示数据，分析内容仅作界面展示；此图使用空目录，没有真实账号和模型。

自动下载不可用时，如何手动准备固定版本模型

程序使用固定上游模型 ZIP，约 599 MB，SHA256：

abdd8bc363726e40a94e77750d09828cd681e08876e13c9be6ef776a3a24c4af

这是模型文件来源，不是 QQVibe 的应用更新源。自动下载不可达时，可以从固定 ONNX 版本获取：

  • model.onnx
  • onnx_config.json
  • rl_agent_config.json
  • README.md
  • tokenizer/tokenizer.json
  • tokenizer/tokenizer_config.json

保留 tokenizer 子目录，再在 QQVibe 点「选择目录」。请使用这组固定版本文件，不要混用其他模型或随意替换文件。程序会检查所需文件，许可来源见模型说明。

可选：使用 API 或 Ollama

第一次使用推荐本地 Laya / CPU。如果你已经有自己的模型服务，可以在 「模型来源」中切换到 「API 接入」，无需下载 Laya。

  1. 选择服务对应的 「接口协议」。
  2. 按服务商说明填写 Base URL 和自己的 API Key。
  3. 点 「获取模型列表」后选择模型，或手动填写 「模型 ID」。
  4. 填写该服务支持的 「上下文大小」。
  5. 点 「测试连接」，再点 「保存并启用」。

Chat Completions 对应界面中的 「Completions（旧版）」。Ollama 使用 「Ollama 兼容」，先自行启动本地 Ollama 并准备模型；常用本机地址为 http://127.0.0.1:11434。

真实 API/Ollama 服务尚未完成验证；目前的本机假服务检查只证明界面和流程，不证明你的服务能完成分析。API 模式会把需要分析的聊天片段发送给你填写的服务，可能产生费用。编程助手订阅不等于这个服务的额度；暂停前已经发出的请求仍可能计费。不要把 Key 发给同学或写在反馈里。

JSON 聊天记录导入

1.0.0 包含主流 JSON 与手动字段映射，以及 QCE 6.3.0/6.3.1 的自动时间、消息编号和文本类型适配。

在「设置 → 导入聊天 JSON」选择文件，先点「预览」。程序只在本机读取，确认导入前不会写入聊天库。预览会显示发送者、时间、正文样本、有效/拒绝/冲突条数；请核对后再确认。

可识别的内容

  • QCE V6 单文件 JSON、manifest.json 和完整 JSONL 分块目录；也适配使用相同消息字段的旧版 QCE 导出。
  • 顶层消息数组、messages / records / data.messages 等嵌套列表。
  • JSONL / NDJSON，一行一条消息；多行 JSONL 即使扩展名是 .json 也按内容识别。
  • QQ 的 ChatLab JSON/JSONL、常见 OneBot 和 NapCat 消息字段。
  • UTF-8，以及带 BOM 编码标记的 UTF-16 / UTF-32。

这不代表任意 JSON 都是聊天记录，也不保证所有软件版本的导出都自动识别。其他平台声明的记录不能归入 QQ 账号；没有发送者、正文或时间的内容不会凭空补齐。

没有自动识别时

1.0.0 会自动读取 QCE 的 timestamp 毫秒时间戳，保留原始 id 与毫秒精度，time 作为展示字段。旧格式的 ISO 时间仍兼容。当前使用 0.1.2 时，如出现时间字段冲突，可指定 timestamp 并选择「毫秒」后重新预览；核对几条消息的日期与时刻再导入。

展开「识别不准确？指定字段与会话」，按原文件填写：

设置示例
消息列表位置顶层数组填 /，嵌套列表填 /payload/entries；界面会列出发现的列表
正文、发送者、时间字段content.text、sender.uin、timestamp；特殊字段名可使用 /content/text 形式

只有昵称时，预览会提供「某昵称对应的 QQ 号」输入框。填写正确 QQ 号后再次预览。本人身份仍需要明确确认，不能把对方选成本人；一个文件内出现多个群或多个单聊时，需要分别导出/选择单个会话列表。

修改文件或字段设置后，旧预览不能继续确认，需要重新预览。存在坏行时会说明拒绝原因，只有明确选择跳过后才允许导入其余记录。

大文件与重复消息

程序分批读取、用临时数据库暂存，不将整个聊天数组放入内存。当前每次上限为 2 GiB、200 万条；manifest 的全部消息分块合计计算，单条消息仍有约 2 Mi 字符的解析上限。更大范围可按时间分次导出，分块目录要完整保留并选择 manifest.json。

有原始消息 ID 时，在相同账号和会话中按对应来源的 ID 去重。没有 ID 时按文件快照和行号保留：同一文件重复导入会去重，文件内同文消息不会被合并；不同文件、不同时间范围、不同封装方式的重叠消息可能重复，因此优先使用含原始 ID 的导出。

群号、QQ 号和对方 UID 不会自动编造。缺失身份的文件可以先查看提取样本，但要补足身份才能正式导入。图片/语音等保留为非文本记录，本功能不做图片 OCR 或语音转写。

预览失败时

报错会区分格式/编码不完整、列表位置不明、缺少字段、身份冲突、文件大小限制、权限和存储问题。经过链接或云端占位路径的文件，复制完整导出到普通本地文件夹后重试。

如仍失败，反馈 QQVibe 版本、导出工具和版本、文件大小、报错文字即可。必要时提供仅保留字段结构的合成样例，不需要发送完整私人聊天。

QQVibe 自动更新

1.0.0 包含应用内更新。旧 0.1.2 仍需手动迁移一次，此后可以在应用内检查和下载更新。

使用流程

安装支持自动更新的新版本后，在「设置 → 关于 → 当前版本」打开软件更新窗口。

  • 默认自动检查更新，启动后延迟检查，正常每 24 小时最多检查一次；也可手动点「检查更新」。检查失败会明确显示网络、超时或发布文件问题，不当作最新版本。
  • 新用户默认「仅正式版」渠道；需要试用预发布时可选择「预发布版（含正式版）」。已有渠道选择保留。版本数字与 GitHub 的预发布标记是两项独立信息。
  • 自动下载默认关闭。开启后，后台检查发现新版会下载标准包；点击「下载更新」也可手动下载。
  • 下载完成后点击「重启并更新」，并在提示中确认。下载本身不会退出程序。正在导入、分析、备份或下载模型时会提示稍后重试。
  • 已有聊天、设置和模型会保留，更新失败会尝试恢复原程序。更新前建议使用「备份全部数据」。空间不足或文件仍被占用时，不替换当前程序。
  • 更新包签名由程序内固定的公钥验证。与 Windows 可执行文件签名不同，首次下载的 Windows 安全提示仍按实际情况处理。

首次迁移

0.1.2 没有启用应用内更新，所以首次迁移仍需下载支持更新的新包，并按备份升级说明迁移数据。后续发布版本提供匹配的签名更新附件后，才能从应用内升级。

发布要求

每个可自动安装的版本需要 Windows x64 标准 ZIP、update-manifest.json、update-manifest.sig、UPDATE-SHA256SUMS.txt。完整包用于首次下载；已有模型通过标准包更新并保留，避免每次重复下载模型。

本次 1.0.0 为首个正式发布版本。其他电脑和网络环境按实际反馈继续验证；更新失败时请保留提示并使用手动下载入口。

QCE 检测与最小修复

工具版本：1.0.0。适用于 Windows 10/11 的 QCE 本机安装；使用系统自带 Windows PowerShell 5.1 和 .NET，不需要安装 Python、Node 或额外模块。

最少操作

  1. 把检测 ZIP 全部解压，双击 检查并修复QCE.cmd。集成构建版 QQVibe 设置的「QQ 连接与自动同步」里也有入口；公开的 0.1.1 原包未包含这一新增功能。
  2. 窗口自动检测。若「最小修复并复检」可以点击，点一次，等待复检结果。
  3. 显示「后台和二维码已就绪」时，回 QCE 完成扫码，然后在 QQVibe 点「连接本机 QQ / QCE」。扫码需要本人操作，工具不会替你登录。

如果 QCE 是自定义安装，工具先读取安装器自己记录的位置；找不到时点「选择 QCE 目录」，选含 launcher-user.bat 的文件夹。便携 QQ 未被识别时点「选择 QQ.exe」。已运行的未知 NapCat 实例、权限不足或路径含链接时，工具会显示未确认，不靠结束其他程序来修复。

检查范围

共 17 个关口：系统、QCE 安装位置、启动方式、关键组件、QQNT、后台保存的 QQ 路径、WebUI 配置、NapCat 后台端口、WebUI 认证、QQ 登录、二维码、QCE 导出接口、系统网络状态、VC++ DLL 线索、磁盘空间、最近启动错误、版本组合。

端口检测会包含配置端口和 QCE 安装器的默认候选范围。只连接本机 127.0.0.1，不使用系统代理、不跟随 HTTP 跳转。认证后只检查固定的登录、信息与状态接口；不读取好友、群、聊天或数据库。

「通过」仅指该项实际检查结果。端口有响应不等于 NapCat 身份正确；二维码可获取不等于 QQ 已登录；HTTP 200 不等于 QCE 结构正确；系统网络可用不等于 QQ 登录服务器可达。未知版本与跨电脑运行不被写成通过验收。

最小修复

  • 保存的 QQ 路径失效、或你明确选择另一份 QQNT：备份后保存通过 QQNT 文件结构检查的路径。
  • 已有 WebUI 配置明确关闭、或端口值无效：后台没有运行时备份后启用，非法端口改为 6099，保留 token 和其他字段。配置无法读取时不重建凭证。
  • Shell 关键文件齐全、QQNT 已确认、无已运行的同名/未知后台、登录服务没有监听：隐藏启动一次现有 launcher-user.bat，最多等待 35 秒，再检查实际接口。

每项修复前再次检查条件。同一安装目录的修复互斥，避免多个窗口重复启动。原配置备份在原文件旁，文件名含 .doctor-backup-；不要把这些含配置的备份当作反馈发送。

工具不删除数据、不清除 token、不关闭桌面 QQ、不自动升级/降级 QQ。Framework 不套用 Shell 的启动修复。组件缺失、运行库缺失、版本不兼容或无法确认的权限问题，会给出对应诊断，不做盲目覆盖安装。QCE 官方安装入口：固定 6.3.0；QQ 官方入口：QQ；日志明确提示 VC++ DLL 缺失时使用微软 x64 运行库。

如果后台已经存在但没有监听，工具保留进程，报告未通过；不自动结束无法确认归属的 QQ 或 NapCat。

不需要翻日志的反馈

点「保存匿名报告」，把生成的 JSON 发给提供软件的同学即可。报告只包含检查结果、版本、错误类别、修复与复检结果，不包含账号、聊天、token、二维码、原始日志或本机安装路径。

工具工作报告默认写在 %LOCALAPPDATA%\QQVibeDoctor；这是匿名报告目录。运行日志仍由 QCE 保存。工具只读取最近一段，识别最新启动标记；旧日志不用于推断当前错误。

标准包需要自己获取模型；完整包已保留固定模型来源与许可，见模型来源和许可。QQ 和 QCE 是另外安装的外部程序，升级它们后请先核对账号与连接状态。

备份、更新与回到旧版本

QQVibe 把消息与分析结果保存在这份程序自己的文件夹中。换一个新解压目录，不会自动显示旧目录的消息；请按下面的步骤备份和恢复。

先保存备份

  1. 在旧版 QQVibe 中打开设置，找到「完整数据备份与恢复」。
  2. 点「备份全部数据」，保存到自己容易找到的位置。
  3. 保留旧程序整个文件夹和原 ZIP，暂时不要删除。

备份包含聊天、账号和分析结果，是私人文件。不要随问题反馈上传，也不要发到群里。模型文件不包含在备份内；自己选择的模型文件夹需要另行保留。

从 0.1.2 或更早版本迁移到 1.0.0

  1. 正常退出旧版 QQVibe。
  2. 下载新版程序包，完整解压到另一个文件夹，不覆盖正在运行的旧版。
  3. 打开新版的 QQVibe.exe，进入设置，点「恢复备份」。
  4. 选择刚保存的备份，核对提示中的账号和会话范围，再确认恢复。
  5. 等待程序重新打开，检查会话、消息和分析结果是否还在，再确认 QQ / QCE 连接。

新版默认浅色。恢复旧设置后如果仍为深色，到「主题外观」选择「浅色模式」。程序不会强行覆盖你保存过的主题。

新版打不开时

关闭新版，回到保留的旧程序文件夹，打开旧版 QQVibe.exe。需要时在旧版恢复原备份。先保留错误提示和两个目录，按反馈模板说明发生在哪一步，不要用删除数据或反复重装来掩盖现象。

换电脑的注意事项

账号凭证受当前 Windows 账号的加密保护。换电脑或 Windows 账号后，需要重新输入自己电脑上的 QCE token / API Key，并明确重新连接；不能把别人机器上的凭证当作通用设置。另一电脑的恢复流程仍在验证，原目录和备份应保留到新机器确认可用。

数据具体位置为 win-unpacked/resources/client/QQVibeData。普通使用和更新不需要手动编辑里面的文件。从旧版首次迁移需按上述步骤手动完成。1.0.0 之后可在「设置 → 关于 → 当前版本」检查、下载并确认重启更新；自动更新说明。应用更新不会替换你的 QQ 或 QCE。

应用内更新与回退

下载完成后再确认「重启并更新」。已有本地模型、聊天和配置会保留；程序保留上一版副本，验证失败时尝试恢复。主动回退会保留当前数据，但旧版可能不兼容未来的新数据格式，建议先备份。
