# QCE 检测与最小修复

工具版本：1.0.0。适用于 Windows 10/11 的 QCE 本机安装；使用系统自带 Windows PowerShell 5.1 和 .NET，不需要安装 Python、Node 或额外模块。

## 最少操作

1. 把检测 ZIP **全部解压**，双击 **检查并修复QCE.cmd**。集成构建版 QQVibe 设置的「QQ 连接与自动同步」里也有入口；公开的 0.1.1 原包未包含这一新增功能。
2. 窗口自动检测。若「最小修复并复检」可以点击，点一次，等待复检结果。
3. 显示「后台和二维码已就绪」时，回 QCE 完成扫码，然后在 QQVibe 点「连接本机 QQ / QCE」。扫码需要本人操作，工具不会替你登录。

如果 QCE 是自定义安装，工具先读取安装器自己记录的位置；找不到时点「选择 QCE 目录」，选含 `launcher-user.bat` 的文件夹。便携 QQ 未被识别时点「选择 QQ.exe」。已运行的未知 NapCat 实例、权限不足或路径含链接时，工具会显示未确认，不靠结束其他程序来修复。

## 检查范围

共 17 个关口：系统、QCE 安装位置、启动方式、关键组件、QQNT、后台保存的 QQ 路径、WebUI 配置、NapCat 后台端口、WebUI 认证、QQ 登录、二维码、QCE 导出接口、系统网络状态、VC++ DLL 线索、磁盘空间、最近启动错误、版本组合。

端口检测会包含配置端口和 QCE 安装器的默认候选范围。只连接本机 `127.0.0.1`，不使用系统代理、不跟随 HTTP 跳转。认证后只检查固定的登录、信息与状态接口；不读取好友、群、聊天或数据库。

「通过」仅指该项实际检查结果。端口有响应不等于 NapCat 身份正确；二维码可获取不等于 QQ 已登录；HTTP 200 不等于 QCE 结构正确；系统网络可用不等于 QQ 登录服务器可达。未知版本与跨电脑运行不被写成通过验收。

## 最小修复

- 保存的 QQ 路径失效、或你明确选择另一份 QQNT：备份后保存通过 QQNT 文件结构检查的路径。
- 已有 WebUI 配置明确关闭、或端口值无效：后台没有运行时备份后启用，非法端口改为 6099，保留 token 和其他字段。配置无法读取时不重建凭证。
- Shell 关键文件齐全、QQNT 已确认、无已运行的同名/未知后台、登录服务没有监听：隐藏启动一次现有 `launcher-user.bat`，最多等待 35 秒，再检查实际接口。

每项修复前再次检查条件。同一安装目录的修复互斥，避免多个窗口重复启动。原配置备份在原文件旁，文件名含 `.doctor-backup-`；不要把这些含配置的备份当作反馈发送。

工具不删除数据、不清除 token、不关闭桌面 QQ、不自动升级/降级 QQ。Framework 不套用 Shell 的启动修复。组件缺失、运行库缺失、版本不兼容或无法确认的权限问题，会给出对应诊断，不做盲目覆盖安装。QCE 官方安装入口：[固定 6.3.0](https://github.com/shuakami/qq-chat-exporter/releases/tag/v6.3.0)；QQ 官方入口：[QQ](https://im.qq.com/)；日志明确提示 VC++ DLL 缺失时使用[微软 x64 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)。

如果后台已经存在但没有监听，工具保留进程，报告未通过；不自动结束无法确认归属的 QQ 或 NapCat。

## 不需要翻日志的反馈

点「保存匿名报告」，把生成的 JSON 发给提供软件的同学即可。报告只包含检查结果、版本、错误类别、修复与复检结果，不包含账号、聊天、token、二维码、原始日志或本机安装路径。

工具工作报告默认写在 `%LOCALAPPDATA%\QQVibeDoctor`；这是匿名报告目录。运行日志仍由 QCE 保存。工具只读取最近一段，识别最新启动标记；旧日志不用于推断当前错误。

## 验证边界

开发机已检查 Windows PowerShell 5.1、GUI、配置备份、重复启动防护和真实 loopback 假服务的 HTTP 流程。另一电脑上这次「无端口监听」的实际原因和修复结果仍需运行工具后确认。
